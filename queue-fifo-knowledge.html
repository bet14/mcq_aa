Queue — FIFO Data Structure

A linear data structure where elements follow First In, First Out order. The first element added is the first element removed.

O(1)
Enqueue (add to back)
O(1)
Dequeue (remove from front)
O(1)
Peek (view front)
O(n)
Space complexity
The FIFO Principle
Elements enter at the back (rear) and leave from the front. Insertion order is strictly preserved — no element can skip the line.

Key Properties

PropertyDescription
OrderingStrictly FIFO — insertion order always preserved
Access patternOnly the front element is removable; only the front element is peekable
Pointer-based removalFront pointer advances on dequeue — no shifting of elements (O(1))
ImplementationsCircular array, linked list, two-stack simulation

Where Queues Appear

Task Scheduling
OS process queues, print spoolers, job queues — first submitted, first executed.
Buffer Management
Network packet buffers, keyboard input, I/O streams — data flows in arrival order.
Breadth-First Search
Graph traversal that processes nodes level by level, using a queue to track the frontier.

Core Operations

Pseudocode, line-by-line annotation, and complexity analysis for Enqueue, Dequeue, and Peek.

Enqueue — Add to Back

function enqueue(queue, element):
    // Append element to the rear of the queue
    queue.data[queue.back] ← element
    queue.back ← queue.back + 1
    queue.size ← queue.size + 1
LineActionNotes
queue.data[queue.back] ← elementWrite element at current rear indexIn a circular buffer: use back % capacity
queue.back ← queue.back + 1Advance the rear pointerPoints to the next free slot
queue.size ← queue.size + 1Increment size counterUsed to detect full / empty conditions
CaseTimeReason
AnyO(1)Single write + pointer increment, no traversal

Dequeue — Remove from Front

function dequeue(queue):
    if queue.size == 0:
        raise UnderflowError("Queue is empty")
    element     ← queue.data[queue.front]
    queue.front ← queue.front + 1
    queue.size  ← queue.size  - 1
    return element
LineActionNotes
if queue.size == 0Guard against underflowMust check before accessing data
element ← queue.data[queue.front]Read the front elementDoes not shift the array — just reads the pointer
queue.front ← queue.front + 1Advance the front pointerElement is logically removed; no actual deletion
return elementReturn the removed value
CaseTimeReason
Non-emptyO(1)Single read + pointer increment, no shifting
Empty queueErrorRaises UnderflowError immediately
Why not O(n)?
A naive array implementation would shift all elements left on dequeue, giving O(n). The pointer approach avoids this: the front pointer simply advances, and the slot is logically vacated. A circular buffer reuses those slots so memory is not wasted.

Peek / Front — View Without Removing

function peek(queue):
    if queue.size == 0:
        raise UnderflowError("Queue is empty")
    return queue.data[queue.front]  // front pointer NOT modified
LineActionNotes
if queue.size == 0Guard against underflowIdentical check to dequeue
return queue.data[queue.front]Read front elementNo pointer is modified — queue state unchanged
CaseTimeKey difference from Dequeue
Non-emptyO(1)Read only — front pointer is NOT advanced

Example 3 — BFS Traversal

Breadth-First Search uses a queue to explore a graph level by level, guaranteeing shortest-path order in unweighted graphs.

Graph Structure
Starting from A: A → B, C  |  B → D, E  |  C → F

BFS Pseudocode

function bfs(graph, start):
    visited ← Set()
    queue   ← Queue()

    enqueue(queue, start)
    visited.add(start)

    while queue is not empty:
        node ← dequeue(queue)
        process(node)                    // visit the node

        for each neighbor in graph[node]:
            if neighbor not in visited:
                visited.add(neighbor)
                enqueue(queue, neighbor)
