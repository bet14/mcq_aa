Algorithm Summary Table

Note: “Intersection” is interpreted as finding common elements between two arrays or lists.
Criteria Linear Search Binary Search Bubble Sort Merge Sort Intersection
Algorithm Searches for a target by checking elements one by one from the beginning to the end. Searches for a target in a sorted array by repeatedly dividing the search range in half. Sorts an array by repeatedly comparing adjacent elements and swapping them if they are in the wrong order. Sorts an array by dividing it into halves, sorting each half, and then merging them. Finds elements that appear in both collections. It can be implemented using nested loops, sorting, or a hash set.
Pseudo code 
LinearSearch(arr, target):
    for i from 0 to length(arr) - 1:
        if arr[i] == target:
            return i
    return -1
 
BinarySearch(arr, target):
    left = 0
    right = length(arr) - 1

    while left <= right:
        mid = (left + right) // 2

        if arr[mid] == target:
            return mid
        else if arr[mid] < target:
            left = mid + 1
        else:
            right = mid - 1

    return -1
 
BubbleSort(arr):
    n = length(arr)

    for i from 0 to n - 1:
        swapped = false

        for j from 0 to n - i - 2:
            if arr[j] > arr[j + 1]:
                swap arr[j], arr[j + 1]
                swapped = true

        if swapped == false:
            break

    return arr

        return arr

    return Merge(left, right)

Merge(left, right):
    result = []

    while left and right are not empty:
        if left[0] <= right[0]:
            append left[0] to result
            remove left[0]
        else:
            append right[0] to result
            remove right[0]

    append remaining elements
    return result
 
Intersection(arr1, arr2):
    set1 = empty set
    result = empty list

    for x in arr1:
        add x to set1

    for y in arr2:
        if y in set1:
            add y to result

    return result
Best case time complexity O(1)
Best case happens when the target is the first element. Only one comparison is needed. 		O(1)
Best case happens when the middle element is exactly the target. Only one comparison is needed. 		O(n)
With optimized Bubble Sort, if the array is already sorted, the algorithm performs only one full pass and no swaps. 		O(n log n)
Merge Sort always divides the array and merges all elements, even if the array is already sorted. 		O(n + m)
Using a hash set, the algorithm inserts all elements of the first array and checks all elements of the second array.
Worst case time complexity O(n)
Worst case happens when the target is at the last position or not present. The algorithm must check every element. 		O(log n)
Each comparison halves the search space. In the worst case, the search continues until the range becomes empty. 		O(n²)
Worst case happens when the array is reverse sorted. Many adjacent swaps are required. 		O(n log n)
The array is divided into log n levels, and each level requires O(n) merging work. 		O(n + m)
Using a hash set, every element of both arrays is still processed once.
Average case time complexity O(n)
On average, the target may be somewhere in the middle, so about half of the elements are checked. Constants are ignored, so it is still O(n). 		O(log n)
On average, the search space is repeatedly halved until the target is found or confirmed absent. 		O(n²)
For a randomly ordered array, many comparisons and swaps are needed across multiple passes. 		O(n log n)
Merge Sort always follows the same divide-and-merge structure regardless of input order. 		O(n + m)
Using a hash set, insertion and lookup are average O(1), so each element is processed once.
Best case space complexity O(1)
Only a few variables are used, such as the loop index. No extra data structure is needed. 		O(1)
Iterative Binary Search only uses variables such as left, right, and mid. 		O(1)
Bubble Sort sorts in place and only uses temporary variables for swapping. 		O(n)
Merge Sort needs extra arrays or lists for merging. Even in the best case, extra memory is required. 		O(n)
A hash set is created to store elements of the first array.
Worst case space complexity O(1)
The algorithm uses constant extra memory regardless of input size. 		O(1)
For the iterative version, only a few variables are used. If implemented recursively, it can be O(log n) because of the call stack. 		O(1)
Sorting is done in place. No additional array is needed. 		O(n)
Extra memory is needed to store temporary subarrays during merging. Recursive calls also add stack space. 		O(n + k)
The hash set stores elements of the first array, and the result list stores k common elements. If output is counted, it may be simplified as O(n + m).
Average case space complexity O(1)
The number of extra variables does not depend on the array size. 		O(1)
The iterative version uses constant memory in normal cases. 		O(1)
Bubble Sort does not need extra memory proportional to the input size. 		O(n)
Temporary arrays are needed during the merge process. 		O(n + k)
The hash set requires space for elements of the first array, and the result list stores common elements.
