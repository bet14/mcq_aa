Overview: Two Ways to Explore a Graph

Depth-First Search (DFS) and Breadth-First Search (BFS) are the two fundamental graph traversal algorithms. Both visit every vertex reachable from a start vertex exactly once, and both run in linear time on an adjacency-list representation. They differ in one decision only: which discovered-but-unprocessed vertex to expand next. DFS expands the most recently discovered vertex (LIFO — a stack), diving as deep as possible before backtracking. BFS expands the earliest discovered vertex (FIFO — a queue), sweeping outward level by level.

Conceptual flow, side by side

DFS — go deep, then backtrack

Push start vertex onto the stack
Pop the top vertex u
If u already visited: skip (stale entry)
Mark u visited (process it)
Push all unvisited neighbors of u
Repeat until the stack is empty

BFS — expand the frontier evenly

Mark start discovered, put it in the queue
Dequeue the front vertex u
Process u (it is now visited)
For each neighbor v not yet discovered:
Mark v discovered and enqueue it
Repeat until the queue is empty
The only structural difference is the container. Replace the stack in DFS with a queue and the algorithm becomes BFS. LIFO order produces deep, branch-committed exploration; FIFO order produces concentric, level-by-level exploration. Everything else — visited set, neighbor iteration, linear cost — is identical.

DFS — Depth-First Search

DFS commits to one neighbor, then one of its neighbors, and so on, until it hits a vertex with no unvisited neighbors (a dead end). It then backtracks to the most recent vertex that still has unexplored options. The LIFO stack implements this automatically: the most recently pushed vertex is the next one expanded.

Iterative pseudocode (explicit stack)

1DFS-Iterative(G, s):
2    stack ← empty stack;  push(stack, s)
3    visited ← ∅
4    while stack is not empty:
5        u ← pop(stack)
6        if u ∈ visited: continue      // stale entry — skip
7        add u to visited                 // u is processed HERE
8        for each v in Adj[u], in reverse order:
9            if v ∉ visited:
10                push(stack, v)

Line-by-line annotation

LineWhat it doesCost contribution
2–3Initialize: start vertex on the stack, empty visited setO(1)
4–5Loop until no pending vertices remain; pop the most recentEach push is popped once
6A vertex can be pushed several times (reached from several neighbors); only the first pop processes it — later pops are stale and skippedO(1) per pop
7Marking at pop time defines the visit orderO(1), executed exactly V times
8–10Scan the adjacency list of u; reverse push order makes pops follow natural (e.g. alphabetical) order. Across the whole run every edge is scanned at most twice (undirected) or once (directed)Σ deg(u) = O(E)

Recursive pseudocode

1DFS-Recursive(G, u, visited):
2    add u to visited                 // u processed at call entry
3    for each v in Adj[u]:
4        if v ∉ visited:
5            DFS-Recursive(G, v, visited)

The recursive version uses the language call stack instead of an explicit one. It is shorter and never holds duplicates, but recursion depth can reach V — on large or path-shaped graphs this risks stack overflow, which is why the iterative form is preferred in production. Both produce a depth-first order; they may differ slightly in tie-breaking depending on push order.

Time and space complexity

AspectAdjacency listAdjacency matrixWhy
TimeO(V + E)O(V²)Each vertex processed once (O(V)); neighbor scan totals all degrees (O(E) list) or a full row of V entries per vertex (matrix)

Best vs worst case. Traversal always touches every reachable vertex, so time is Θ(V+E) regardless of input shape — there is no "lucky" early exit unless searching for a specific target found early. Space is what varies: a path graph drives recursive DFS to depth V (worst), while a star graph keeps depth at 2 (best).

How the walk proceeds — 3 interactive traces

Use Next / Prev to step through. At every step the note explains the pop, the marking, and the pushes. Watch how DFS dives along one branch and how stale stack entries (a node pushed twice via different neighbors) get skipped — that skip is the backtracking in action.

Trace 1 — General undirected graph (16 nodes)

Neighbors are explored alphabetically. Several nodes are reachable by more than one route, so duplicate stack entries and skip-steps occur.

Trace 2 — Complete binary tree (15 nodes)

On a tree, DFS from the root with children pushed right-then-left yields exactly the preorder traversal: root, entire left subtree, entire right subtree.

Trace 3 — Directed acyclic graph (15 nodes)

Edges are one-way (arrowheads). DFS follows out-edges only. Nodes with several in-edges (diamond shapes) are pushed multiple times but visited once — DFS on DAGs is the engine behind topological sorting.

BFS — Breadth-First Search

BFS explores in concentric rings: first the start vertex (distance 0), then everything one edge away, then two edges away, and so on. The FIFO queue guarantees that no vertex at distance k+1 is processed before all vertices at distance k — which is precisely why BFS computes shortest paths in unweighted graphs.

Pseudocode (queue)

1BFS(G, s):
2    queue ← empty queue
3    mark s as discovered;  enqueue(queue, s)
4    while queue is not empty:
5        u ← dequeue(queue)
6        process u                        // u is visited HERE
7        for each v in Adj[u]:
8            if v is not discovered:
9                mark v discovered;  enqueue(queue, v)

Line-by-line annotation

LineWhat it doesCost contribution
2–3Initialize; the start vertex is the entire distance-0 levelO(1)
4–5Dequeue the oldest discovered vertex — FIFO enforces level orderEach vertex enqueued once, dequeued once: O(V)
6Processing point; record distance/parent here for shortest-path reconstructionO(1) per vertex
7–9Marking at enqueue time (not dequeue) guarantees each vertex enters the queue at most once — no stale entries, unlike the iterative-DFS variantΣ deg(u) = O(E)
Shortest-path property. When v is first discovered from u (line 8–9), dist(v) = dist(u) + 1, and this is provably the minimum number of edges from s to v. Store parent[v] = u at that moment and walk parents backward to reconstruct the path.

Time and space complexity

AspectAdjacency listAdjacency matrixWhy
TimeO(V + E)O(V²)One enqueue/dequeue per vertex; each adjacency list scanned once
Space — queueO(V) worst caseBounded by the widest level (frontier); a star graph puts V−1 vertices in the queue at once
Discovered setO(V)One flag per vertex
Best vs worst case. Like DFS, full BFS is Θ(V+E) — every reachable vertex and edge is examined. The shape-dependent quantity is queue memory: deep narrow graphs (paths) keep the frontier at size 1 (best); wide shallow graphs (stars, dense levels) inflate it toward V (worst). Note this is the mirror image of DFS's memory behavior.

Trace 1 — General undirected graph (16 nodes)

Following out-edges only, BFS discovers each diamond-join node the first time any in-edge reaches it; the discovered-check stops later in-edges from re-enqueueing it.
